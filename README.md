# Accept Papers, Please

Браузерная игра о подаче документов по другую сторону стекла. Расширение существующего прототипа на **TypeScript + Phaser 3 + Vite**, без backend, CDN или внешних API во время игры.


## Обновление: документы, пауза и кадры NPC

Логическая сцена остаётся **960×540**. Папки отображаются как «Документы» и «Справки» (идентификаторы `folder1` / `folder2` прежние). Стол имеет статичную тканевую фактуру, лоток — металлические бортики, рядом расположена памятка. Кабинеты, рука, персонажи и паспорт пока используют временную графику.

Кнопки **МЕНЮ** и **ПАУЗА** доступны также при чтении, в мини-играх и при разговоре с NPC. Пауза запускает отдельную сцену `Pause`, приостанавливая обновление Game, её часы, tweens, таймеры диалогов и руку. Поле ФИО временно скрывается, но сохраняет ввод. Продолжение восстанавливает то же состояние. Выход в главное меню требует подтверждения; только подтверждённый выход начинает незавершённый день заново.

Стартовое объявление скрывается после 15 секунд активного времени. Сюжетные объявления используют отдельную логику и не исчезают по этому правилу. Реплики игрока живут 3000 мс (`playerReplyDurationMs`). Высота окна сотрудника подстраивается под текст. Перетаскиваемые документы имеют depth=55, обычные открытые — 30; декоративные надписи — 3–5, диалоги — от 60.

`systems/runPlan.ts` создаёт и проверяет сохраняемый план всего прохождения: три разных разворота паспорта, три разных листа «Документов», разные листы «Справок» для дней 2/3. План хранится в `Save.plan` и не меняется при повторе дня/перезагрузке. Старые сохранения получают план при первом продолжении. Новый старт создаёт новый план. Правильное фото случайно выбирается из двух близких вариантов. Три набора размеров перемешиваются между днями:

- 48×60, 54×60, 72×84;
- 54×66, 60×66, 36×48;
- 48×72, 54×72, 72×96.

Линейка: 48 px/вершок, малое деление 6 px (1/8). Размер рамки берётся из выбранного набора, портрет вписывается пропорционально. Основной PNG лица — `portrait`. Цвет бумаги хранится в `Page.paperColor` и одинаков на столе и в чтении. Обычный просмотр — лист 318×450, с прокруткой колесом или стрелками. Паспорт отрисовывается `components/Passport.ts`: обложка и три вертикальных разворота; кнопка «Читать» показывает шуточную записку, сохраняя страницу.

### Как подключить 2, 4 или больше кадров персонажа

Файл `data/dialogues.ts` содержит `npс`-конфигурацию (имя переменной в коде — `npcs`). Уже предусмотрены visitor-1: 2 кадра, visitor-2: 2 кадра, visitor-3: 4 кадра, visitor-4: 2 кадра. Число NPC и длина массива кадров не зашиты в сцену. Все кадры одного NPC рисуйте на одинаковом холсте 120×180 и с одинаковой опорной точкой ног.

```ts
npcs['visitor-3'] = {
  id: 'visitor-3', name: 'Ваше имя персонажа', sprite: 'npc-3',
  frames: ['npc-3', 'npc-3-step', 'npc-3-2', 'npc-3-3'],
  frameRate: 6,
  dialogues: ['visitor-3'],
};
dialogues['visitor-3'] = [
  { speaker: 'npc', text: 'Вы тут надолго?' },
  { speaker: 'player', text: 'Только одну бумагу найду.' },
  { speaker: 'npc', text: 'Я тоже так думал вчера.' },
];
```

После генерации записей реестра в `assets/AssetRegistry.ts` назначьте пути:

```ts
assets['npc-3'].path = 'assets/characters/visitor-3/frame-0.png';
assets['npc-3-step'].path = 'assets/characters/visitor-3/frame-1.png';
assets['npc-3-2'].path = 'assets/characters/visitor-3/frame-2.png';
assets['npc-3-3'].path = 'assets/characters/visitor-3/frame-3.png';
```

PNG находятся в `public/` по соответствующим путям. Во время подхода Phaser проигрывает все кадры с заданным `frameRate`, продолжает ту же циклическую анимацию во время разговора. Пауза замораживает этот процесс. Начальная фигура — тёмно-зелёный силуэт; персональная графика появляется при приближении. Для четвёртого NPC достаточно назначить в нужном дне `queue: { at: 25, npc: 'visitor-4', dialogue: 'visitor-4' }`. Можно использовать разные ключи диалогов для одного NPC в разных днях. Если персонаж пока не нужен, не назначайте его в сценарий — наличие записи не вызывает появление автоматически.

29 автоматических тестов: в том числе планы без повторений на 79 seed, сериализация/валидация, новый масштаб фото, пауза, сохранение текущего запроса и проходимость всех трёх запланированных дней. В браузере проверены размеры паспорта, сохранение разворота после паузы, отмена выхода, пауза NPC, исчезновение начального объявления, вертикальное чтение цветного диплома и прокрутка до подписи/печати. Мини-игры подписи и ФИО используют прежнюю логику, пауза действует на всю их сцену. Матрица отдельных прогонов Chrome/Firefox/Safari не выполнялась.

## Запуск и публикация

Рекомендуется Node.js 22 LTS или 24 LTS. Node 23 может выдавать предупреждение Vitest о неподдерживаемой версии.

```sh
npm install
npm run dev
```

Адрес выводится в терминале, обычно `http://127.0.0.1:5173/`.

```sh
npm run typecheck
npm run test
npm run build
npm run preview
```

В `.npmrc` оставлен `legacy-peer-deps=true`: обход сбоя npm 10 при разрешении необязательных peer-зависимостей Vitest. Lock-файл фиксирует версии. Сборка находится в `dist/`. В `vite.config.ts` для сборки задан `base: '/accept-papers-please/'` под имя репозитория GitHub Pages; сервер разработки работает от `/`. При переименовании репозитория обновите `base`.

Для GitHub Pages: отправьте проект в `main`, затем **Settings → Pages → Build and deployment → Source → GitHub Actions**. `.github/workflows/deploy.yml` установит зависимости, выполнит тесты, проверит типы при сборке и опубликует сайт. Workflow можно запустить вручную. Адрес игры: https://a0fail.github.io/accept-papers-please/.

## Игровой цикл

- **День 1, 240 секунд:** паспорт, случайный лист первого файлика, фотография по размеру в вершках. Объявление требует справки о справках; отказ.
- **День 2, 330 секунд:** паспорт, по листу из двух файликов, фотография, согласие на обработку данных с подписью. Отказ из-за отсутствия согласия на очередь.
- **День 3, 420 секунд:** сначала перепечатать ФИО из паспорта, затем обычная подача и повторная подпись. Штамп «ОДОБРЕНО», финальный текст и взлёт самолёта; после анимации доступны новое прохождение и меню.

Один посетитель подходит примерно через 18 / 22 / 28 секунд активного дня. Если игрок занят перетаскиванием, проверкой или мини-игрой, разговор откладывается до безопасного момента. Очень быстрое прохождение может завершиться до события. В разговоре документы и кнопки стола заблокированы, **часы идут**. Кнопка «Далее» переключает реплики. Фоновые ответы героя не блокируют действия и отменяются при более важных событиях.

На меню, переходах, после последней правильной подачи и на финале время остановлено. Чтение, линейка, подпись, ввод ФИО и NPC время расходуют. Скрытие вкладки или потеря фокуса окна ставят основной таймер на паузу. При таймауте мини-игра закрывается, доступен повтор дня. Сохранения localStorage совместимы с предыдущей версией: сохраняются текущий доступный день, пройденные дни и финал, а не середина процедуры. При запрете storage игра продолжает работать.

## Управление

1. Нажмите обложку слева. Стрелки листают паспорт, листы файлика или фотографии.
2. **«Читать»** открывает полный текст крупно. Все названия ведомств, ФИО, номера, даты, печати и подписи доступны здесь. «Вернуться к столу» закрывает просмотр; время не замораживается.
3. Тащите лист или фотографию в лоток и отпустите указатель **внутри лотка**. Неверный предмет возвращается. У файлика забирают только выбранный лист, остальные сохраняются. Весь паспорт передаётся на открытой странице.
4. При запросе фото из лотка появляется угловая измерительная линейка. Потяните её верхнюю планку, затем совместите внутренний угол (ноль обеих шкал) с левым верхним краем фото. Горизонтальная шкала измеряет ширину, вертикальная — высоту. Деления через **1/8 вершка**, 1 вершок = **48 логических пикселей**. Фото А и Б отличаются по ширине ровно на одно малое деление. Размеры на самих фото не подписаны.
5. Нажмите выданный бланк согласия в лотке. Рука отражается от границ как DVD-заставка. Нажмите на бумагу или **Space**, когда **кончик** ручки находится в зелёном поле. Промах не меняет траекторию и не останавливает руку. Подписанный бланк видимо проходит через лоток автоматически.
6. В третьем дне перепечатайте **Подъесауловский Иннокентий Пантелеймонович**. Поле поддерживает кириллицу, вставку, выделение, Backspace и Delete. Регистр и повторные пробелы игнорируются, буквы — нет. Ошибка сохраняет введённую строку. Отложенный бланк можно открыть снова; ввод сохраняется в пределах попытки.

При выходе указателя за canvas, `pointercancel` или потере фокуса перетаскивание бумаги отменяется. Нельзя подать документ дважды или отправить неподписанный бланк.

## Где менять сценарии

| Файл | Назначение |
| --- | --- |
| `src/game/types.ts` | Типы объектов, запросов, дня и мини-игр |
| `src/game/data/character.ts` | Единственный источник ФИО и паспортных данных |
| `src/game/data/documents.ts` | Паспорт, 4 листа первого файлика, 3 листа второго, формы |
| `src/game/data/days.ts` | Последовательность, стартовые предметы, длительность, случайные листы, NPC, объявления, исходы и финальные тексты |
| `src/game/data/minigames.ts` | Размеры фото и масштаб линейки; скорость, границы, точка ручки и поле подписи |
| `src/game/data/dialogues.ts` | Фоновые ответы, диалоги посетителей и пять слотов NPC |

`Request.choices` задаёт допустимые индексы страниц. `attemptDay()` выбирает их **однократно при старте попытки** (резервный путь для сценариев без плана), не изменяя исходную конфигурацию. Открытие папки и ошибки не меняют запрос. В игре используется `runPlan.ts`: повтор дня сохраняет выбор из плана прохождения. `replyPool` задаёт отдельный пул ответа на конкретную просьбу. `issueRuler` включает выдачу линейки. `minigame` задаёт `'signature'` или `'name'`. Убрать повторное подписание в третьем дне можно удалением последнего `sign` из его массива `requests`.

Для нового дня добавьте элемент `days`, не меняя сцену. Промежуточные исходы — `refusal`, финальный — `success`; объявление необязательно. Новый документ добавляется в `DocumentId` и `documents`. Типы объектов: `passport`, `folder`, `photos`, `form`; листы папки имеют независимый `sheetId`.

## Архитектура

Сохранены сцены `Boot` / `Game`, `Session`, `Desk`, `AssetRegistry` и слой данных. Новые компоненты расширяют их:

- `Session` — автомат дня; отдельно `activity`, `eventActive`, `completedForms` и таймер. Модальный интерфейс сам по себе не останавливает часы.
- `mechanics.ts` — чистые функции: случайная конфигурация попытки, оставшиеся листы, масштаб фото, нормализация имени, отражение руки, попадание и безопасный запуск NPC.
- `Desk` — выбор, страницы, отдельные листы и drag/drop; `PhotoRuler` — перенос измерительной шкалы.
- `Minigames` — увеличенное чтение, подпись и имя. Нативный textarea встроен через Phaser DOM в графический бланк; он обеспечивает корректное редактирование русского текста и масштабируется вместе со сценой.
- `QueueEvent` — подход, разговор и уход; `PlayerReply` — отложенные неблокирующие ответы с отменой при смене приоритета.
- `ui.ts` — общие пиксельные панели, кнопки и диалоги, ступенчатая рамка и жёсткая тень. Сотрудник — светлая бумага, игрок — голубовато-зелёный фон.

Обработка документа блокируется синхронно, до запуска анимации. Завершение анимации продвигает процедуру. Очистка экрана отменяет таймеры, tweens, DOM-поле и обработчики, поэтому отложенные события не переходят в следующий день.

## Локальный шрифт и пиксельный рендеринг

Используется **одна гарнитура Tiny5**, Stefan Schmidt / The Tiny5 Project Authors. Локальный файл: `public/assets/fonts/Tiny5.ttf`. Лицензия **SIL Open Font License 1.1**, полный текст: `public/assets/fonts/OFL.txt`.

Источники: [проект Tiny5](https://github.com/Gissio/font_Tiny5), [официальные файлы Google Fonts](https://github.com/google/fonts/tree/main/ofl/tiny5). Загружен официальный variable-файл `Tiny5[BLED,JITT,ROND,wdth,wght].ttf`, сохранён без изменения под коротким именем. Во время игры сетевые шрифты не запрашиваются. Vite упаковывает ссылку CSS с корректным base path.

Лицензию Progresspixel подтвердить не удалось. Pixelify Sans не выбран из-за [известного отсутствия О/П в кириллице](https://github.com/google/fonts/issues/9392). В фактически скачанном Tiny5 проверена cmap: все русские заглавные и строчные, Ё/ё, Ъ/ъ, Ь/ь, цифры и требуемая пунктуация присутствуют. Полное ФИО проверено в браузере.

Текст Phaser использует размеры, кратные 8, resolution=1 и целые координаты. На десктопе сцена 960×540 масштабируется целым множителем (1×, 2×…), с полями по краям. Это предотвращает неодинаковую толщину пикселей при дробном увеличении. На экранах меньше 960×540 предусмотрен FIT-компромисс: игра помещается целиком, но мелкий текст лучше читать в горизонтальном режиме или на десктопе. PNG масштабируются nearest-neighbor.

## Замена графики

`src/game/assets/AssetRegistry.ts` содержит все ключи, пути, размеры, центры `x/y`, `depth` и генератор **простых временных** текстур. Для любой записи задайте, например:

```ts
assets.penHand.path = 'assets/characters/hand-with-pen.png';
```

Файл положите в `public/assets/characters/hand-with-pen.png`. Без начального `/`: загрузчик добавляет `import.meta.env.BASE_URL`. Размеры — ограничивающая рамка, PNG вписывается с сохранением пропорций; прозрачность поддерживается. Ошибка загрузки возвращает геометрическую заглушку и сообщение в консоли. Ассеты не содержат заимствованной графики Papers, Please.

Основные новые ключи:

- `folderShell`, `folderBlue`, `perforation`, `paper` — прозрачный/цветной файлик и слои.
- `${documentId}-cover` — обложка/пачка на столе, подпись остаётся поверх.
- Ключи `Page.asset` — листы и страницы: `application`, `medical`, `permission`, `diploma`, `medical-proof`, `permission-proof`, `diploma-proof`, `passport-0`…`passport-3`, `consent-form`, `queue-consent`.
- `photo-0`…`photo-2` — необязательный индивидуальный арт фотографии, `portrait` — общий временный портрет. Физическая рамка фото определяется конфигурацией размеров, не PNG. Арт вписывается внутрь рамки.
- `ruler` — фон верхней планки. Деления остаются программными и привязаны к измерительной шкале, поэтому замена рисунка не искажает измерения.
- `traySlide`, `consentBlank`, `queueBlank`, `penHand`, `signature` — выдаваемый бланк, крупные формы, рука и подпись.
- `npc-1`…`npc-4`, варианты `-step`, `npc-3-2`, `npc-3-3` — настраиваемые персонажи; ключи кадров задаются в `dialogues.ts`.
- `plane-0`, `plane-1`, `plane-2`, `stamp`, `dialogPanel` — финал и оформление общих панелей.

Остались ключи окружения предыдущего прототипа: сотрудник, стекло, стол, лоток, очередь, стулья, силуэт игрока, рука, часы и стрелка. Лоток автоматически задаёт расширенную область отпускания. Подвижные объекты позиционируются компонентом; реестр задаёт их графику и рамку. **Кончик ручки** привязан к `signatureConfig.tipOffset` относительно центра отображаемого спрайта: при замене PNG проверьте именно эту точку. Визуальные рамки бумаги не влияют на проверку документа.

## Проверки и ограничения

Успешно выполнены `npm run typecheck`, **29 тестов** (`npm run test`) и `npm run build`.

Автоматические тесты проверяют полный порядок трёх дней, отказы и успех, неправильный лист/фото, повторную подачу, запрет незаполненной формы, остаток листов папки, стабильность случайного выбора, точный масштаб фото, русское ФИО, отражение и достижимость подписи, безопасное планирование очереди, работу таймера в мини-играх/диалогах, скрытую вкладку и таймаут.

В браузере пройдены все три дня: большие документы читаются, неверное фото отвергается, NPC блокирует стол и отпускает его, подпись завершается после попадания, ошибочный твёрдый знак не принимается, исправленное ФИО принимается; достигнут финал после анимации. Исправлен и повторно проверен конфликт перетаскивания линейки с анимацией выдачи: ноль шкалы свободно совмещается с краем фото.

Финальные иллюстрации, уникальные портреты пяти NPC и звук **не реализованы**: используются заменяемые геометрические заглушки. Самолёт имеет три слота кадров и простую траекторию разгона/взлёта. Реплики и документы пока тестовые по заданному сценарию. Отдельный полный прогон в Chrome, Firefox и Safari не выполнялся. На маленьком телефоне мелкий текст остаётся ограничением. Общий JS-бандл около 1.53 МБ (354 КБ gzip), в основном Phaser; предупреждение Vite о размере чанка ожидаемо.

### Скорость кадров и текущая компоновка реплик

Скорость каждого персонажа задаётся в `src/game/data/dialogues.ts`, поле `npcs[id].frameRate`. Это кадры в секунду: 2 = 500 мс/кадр, 4 = 250 мс/кадр, 5 = 200 мс/кадр, 10 = 100 мс/кадр. Для желаемого интервала используйте `frameRate: 1000 / intervalMs`, например `frameRate: 1000 / 350`. После изменения обновите страницу целиком, чтобы Phaser пересоздал анимацию. Параметр относится и к подходу, и к разговору. Два кадра при frameRate=4 образуют цикл 500 мс; четыре — цикл 1000 мс.

PNG NPC остаются 120×180. Отображаемый размер уменьшен на 10% (108×162); масштаб `.9` применяется в `QueueEvent.ts` после пропорционального вписывания исходного PNG. Кадры продолжают меняться до ухода NPC и замирают при паузе.

Автоматический ответ героя расположен под текущим окном сотрудника с тем же правым краем. На время NPC-диалога окно сотрудника скрывается, а на его месте растёт колонка реплик NPC/игрока. «Далее» находится под последней репликой; при переполнении колонка автоматически сдвигается вверх. После разговора исходная инструкция сотрудника возвращается. Геометрия колонки — `systems/dialogueLayout.ts`.

Инструкция по подаче теперь написана непосредственно на столе справа сверху. Стопка документов опущена на 6 px, рука и обе части часов сдвинуты вправо на 2 px.
